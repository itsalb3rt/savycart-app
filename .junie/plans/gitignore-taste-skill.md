# Technical Design

### Current State
The `.taste-skill/` directory contains 202 files:
- **`direction.json`** — the essential design direction configuration (style tokens, shell layout, screen patterns, design identity). This is the only file needed for the project.
- **`before/`, `inspect/`, `phase2/`, `phase3/`, `phase4/`, etc.** — subdirectories with generated screenshots (`.jpg`) and `report.json` files from design-taste skill inspection phases.
- **Root-level screenshots** — `after-login-*.jpg` images.

The `.gitignore` currently has no entry for `.taste-skill/`, so all 202 files are tracked in git.

### Proposed Change
Add a single entry to `.gitignore` that keeps `direction.json` while ignoring everything else in `.taste-skill/`:

```

# .taste-skill: keep direction.json, ignore generated screenshots and reports

.taste-skill/*
!.taste-skill/direction.json
```

This keeps the essential design configuration while excluding the 200+ generated artifacts (screenshots and reports) that can be regenerated by the design-taste skill.

### About the report.json files
The 19 `report.json` files in subdirectories (`before/`, `inspect/`, `phase2/`, `phase3/`, `phase4/`) are **generated inspection reports** from the design-taste skill. They contain:
- Viewport metrics (width, height, filled percentage)
- Page analysis (words, images, headings, fonts)
- Motion elements count
- UI fragment analysis

These are diagnostic outputs that the design-taste skill generates during inspection phases. They can be regenerated by running the design-taste skill again, so they don't need to be tracked in git. Only `direction.json` at the root is the essential configuration that defines the design style tokens, shell layout, and screen patterns.

# Delivery Steps

### ✓ Step 1: Add .taste-skill gitignore rules
Add entries to `.gitignore` to exclude generated `.taste-skill` artifacts while keeping `direction.json`.

- Append `.taste-skill/*` and `!.taste-skill/direction.json` to `.gitignore`.
- Run `git rm --cached` on the ignored files (screenshots and reports) to remove them from git tracking while keeping them locally.
